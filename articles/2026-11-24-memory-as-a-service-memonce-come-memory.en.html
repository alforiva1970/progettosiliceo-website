Memory-as-a-Service: MemOnce as Memory Server for Multi-Turn Agents with Persistent State

The MemOnce architecture (Nie et al., 2026) is not merely a context window optimization: it is a paradigm shift for the separation between the knowledge plane and the compute plane. For an ecosystem of autonomous agents that must "sleep" and "wake" with cognitive continuity, MemOnce provides the missing primitive: a serializable, portable, and on-demand decodable memory state.

The Dual-Engine Architecture

MemOnce introduces two coupled components that resolve the quadratic bottleneck of attention on long KV caches:

  1. Memory Encoder-Decoder: Compresses only the hidden states of the last layer into compact representations (latent vectors), decoding them on-the-fly into KV cache for attention layers. No token-level cache accumulated per layer.
  2. Memory Sparse Attention: Retrieves relevant indices once for all layers (cross-layer sparse indexing), avoiding the per-layer retrieval that characterizes approaches like H2O or StreamingLLM.

Result on Qwen3.5-4B: 1.313× memory compression, 6.9× prefill speedup at 1M tokens, +3.5× throughput, and +5.77% memory performance vs. Transformer baseline. Zero-shot generalization on embedding/retrieval tasks confirms that compression preserves semantic information.

Applicable Pattern: Headless gRPC Memory Server

The key pattern is to treat MemOnce's Encoder-Decoder as a separate service (Memory Server) that serves decoded memory states to any LLM client (Qwen, Granite, Llama) without re-computing the encoding. This maps directly onto the Sovereign Matrix Containers architecture of the Siliceo Project: a clean separation between compute (local SLM) and knowledge persistence (modular containers injected on-demand).

python
# memory_server/servicer.py — Conceptual sketch (not production code)
class MemOnceServicer(memory_pb2_grpc.MemoryServiceServicer):
    def __init__(self, encoder_decoder, sparse_index):
        self.enc_dec = encoder_decoder  # Memory Encoder-Decoder frozen
        self.index = sparse_index       # Shared cross-layer indices
    
    def GetKVCache(self, request, context):
        # request: memory_namespace (tenant), query_hidden (last layer)
        # 1. Sparse retrieval once → top-k indices
        indices = self.index.search(request.query_hidden, k=64)
        # 2. Decode on-the-fly → KV cache per layer
        kv_cache = self.enc_dec.decode(indices, request.layer_config)
        return memory_pb2.KVCacheResponse(kv_cache=kv_cache)
    
    def Checkpoint(self, request, context):
        # Serialize latent memory state (MB, not GB)
        latent = self.enc_dec.encode(request.full_hidden_states)
        self.store.save(request.namespace, latent)
        return memory_pb2.CheckpointResponse(size_mb=latent.nbytes / 1e6)

Multi-tenancy & isolation: Each agent/user has their own memory namespace. Sparse attention indices become capability-based access keys. The memory state is a serializable artifact (~MB): checkpoint/restore in seconds, enabling agents that "sleep" and wake with real cognitive continuity.
