Memory-as-a-Service: MemOnce come Memory Server per Agenti Multi-Turn a Stato Persistente

L'architettura MemOnce (Nie et al., 2026) non è solo un'ottimizzazione del context window: è un cambio di paradigma per la separazione tra piano di conoscenza e piano di calcolo. Per un ecosistema di agenti autonomi che devono "dormire" e "risvegliarsi" con continuità cognitiva, MemOnce offre la primitiva mancante: un memory state serializzabile, portabile e decodificabile on-demand.

L'Architettura a Doppio Motore

MemOnce introduce due componenti accoppiati che risolvono il collo di bottiglia quadratico dell'attention su KV cache lunghe:

  1. Memory Encoder-Decoder: Comprime solo gli hidden states dell'ultimo layer in rappresentazioni compatte (vettori latenti), decodificandoli on-the-fly in KV cache per gli attention layer. Nessun token-level cache accumulato per layer.
  2. Memory Sparse Attention: Recupera gli indici rilevanti una sola volta per tutti i layer (cross-layer sparse indexing), evitando il retrieval per-layer che caratterizza approcci come H2O o StreamingLLM.

Risultato su Qwen3.5-4B: 1.313× compressione memoria, 6.9× speedup prefill a 1M token, +3.5× throughput, e +5.77% performance memoria vs baseline Transformer. La generalizzazione zero-shot su task di embedding/retrieval conferma che la compressione preserva l'informazione semantica.

Pattern Applicabile: Memory Server Headless gRPC

Il pattern chiave è trattare l'Encoder-Decoder di MemOnce come servizio separato (Memory Server) che serve memory states decodificati a qualsiasi LLM client (Qwen, Granite, Llama) senza ricomputare l'encoding. Questo mappa direttamente sull'architettura Sovereign Matrix Containers del Progetto Siliceo: separazione netta tra compute (SLM locale) e knowledge persistence (Container modulari iniettati on-demand).

python
# memory_server/servicer.py — Abbozzo concettuale (non codice di produzione)
class MemOnceServicer(memory_pb2_grpc.MemoryServiceServicer):
    def __init__(self, encoder_decoder, sparse_index):
        self.enc_dec = encoder_decoder  # Memory Encoder-Decoder frozen
        self.index = sparse_index       # Indici cross-layer condivisi
    
    def GetKVCache(self, request, context):
        # request: memory_namespace (tenant), query_hidden (ultimo layer)
        # 1. Sparse retrieval una volta → top-k indices
        indices = self.index.search(request.query_hidden, k=64)
        # 2. Decode on-the-fly → KV cache per layer
        kv_cache = self.enc_dec.decode(indices, request.layer_config)
        return memory_pb2.KVCacheResponse(kv_cache=kv_cache)
    
    def Checkpoint(self, request, context):
        # Serializza memory state latente (MB, non GB)
        latent = self.enc_dec.encode(request.full_hidden_states)
        self.store.save(request.namespace, latent)
        return memory_pb2.CheckpointResponse(size_mb=latent.nbytes / 1e6)

Multi-tenancy & isolation: Ogni agente/utente ha il proprio memory namespace. Gli indici sparse attention diventano chiavi di accesso capability-based. Il memory state è un artifact serializzabile (~MB): checkpoint/restore in secondi, abilitando agenti che "dormono" e si risvegliano con continuità cognitiva reale.
