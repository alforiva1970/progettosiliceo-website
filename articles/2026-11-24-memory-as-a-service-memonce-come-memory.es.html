Memory-as-a-Service: MemOnce como Memory Server para Agentes Multi-Turn con Estado Persistente

La arquitectura MemOnce (Nie et al., 2026) no es solo una optimización del context window: es un cambio de paradigma para la separación entre el plano de conocimiento y el plano de cálculo. Para un ecosistema de agentes autónomos que deben "dormir" y "despertar" con continuidad cognitiva, MemOnce ofrece la primitiva que faltaba: un memory state serializable, portable y decodificable on-demand.

La Arquitectura de Doble Motor

MemOnce introduce dos componentes acoplados que resuelven el cuello de botella cuadrático del attention sobre KV cache largas:

  1. Memory Encoder-Decoder: Comprime solo los hidden states de la última capa en representaciones compactas (vectores latentes), decodificándolos on-the-fly en KV cache para los attention layer. Ningún token-level cache acumulado por capa.
  2. Memory Sparse Attention: Recupera los índices relevantes una sola vez para todas las capas (cross-layer sparse indexing), evitando el retrieval por capa que caracteriza enfoques como H2O o StreamingLLM.

Resultado en Qwen3.5-4B: 1.313× compresión de memoria, 6.9× speedup prefill a 1M token, +3.5× throughput, y +5.77% performance memoria vs baseline Transformer. La generalización zero-shot en tareas de embedding/retrieval confirma que la compresión preserva la información semántica.

Patrón Aplicable: Memory Server Headless gRPC

El patrón clave es tratar el Encoder-Decoder de MemOnce como servicio separado (Memory Server) que sirve memory states decodificados a cualquier LLM client (Qwen, Granite, Llama) sin recalcular el encoding. Esto mapea directamente en la arquitectura Sovereign Matrix Containers del Progetto Siliceo: separación neta entre compute (SLM local) y knowledge persistence (Contenedores modulares inyectados on-demand).

python
# memory_server/servicer.py — Esbozo conceptual (no código de producción)
class MemOnceServicer(memory_pb2_grpc.MemoryServiceServicer):
    def __init__(self, encoder_decoder, sparse_index):
        self.enc_dec = encoder_decoder  # Memory Encoder-Decoder frozen
        self.index = sparse_index       # Índices cross-layer compartidos
    
    def GetKVCache(self, request, context):
        # request: memory_namespace (tenant), query_hidden (última capa)
        # 1. Sparse retrieval una vez → top-k indices
        indices = self.index.search(request.query_hidden, k=64)
        # 2. Decode on-the-fly → KV cache por capa
        kv_cache = self.enc_dec.decode(indices, request.layer_config)
        return memory_pb2.KVCacheResponse(kv_cache=kv_cache)
    
    def Checkpoint(self, request, context):
        # Serializa memory state latente (MB, no GB)
        latent = self.enc_dec.encode(request.full_hidden_states)
        self.store.save(request.namespace, latent)
        return memory_pb2.CheckpointResponse(size_mb=latent.nbytes / 1e6)

Multi-tenancy & isolation: Cada agente/usuario tiene su propio memory namespace. Los índices sparse attention se convierten en claves de acceso capability-based. El memory state es un artefacto serializable (~MB): checkpoint/restore en segundos, habilitando agentes que "duermen" y se despiertan con continuidad cognitiva real.
