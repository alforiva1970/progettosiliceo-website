Sovereign Matrix Containers: Separare Calcolo e Conoscenza per un'AI Locale, Privata e Composabile

L'architettura dominante degli LLM oggi fonde due cose distinte: il motore di ragionamento (i pesi del modello) e la conoscenza operativa (fatti, procedure, regole di dominio). Questa fusione crea tre problemi strutturali: modelli gonfiati per memorizzare enciclopedie statiche, aggiornamenti che richiedono ri-addestramento o fine-tuning costosi, e privacy compromessa perché il contesto sensibile deve attraversare API esterne.

La proposta Sovereign Matrix Containers (.smc) — sviluppata all'interno del Progetto Siliceo — inverte il paradigma: il modello locale (SLM compatto) fa solo ragionamento logico e orchestrazione di tool; la conoscenza vive in container modulari, versionati, iniettati on-demand nel context window.

Il runtime SLM non "sa" le aliquote IVA né le procedure di collaudo di una pressa idraulica. Chiede il container pertinente, lo riceve via protocollo locale, lo carica in contesto, ragiona, agisce. Quando la normativa cambia, si aggiorna il container — non il modello.

Formato .smc: Contratto, Non Solo Dati

Un container non è un dump di Markdown. È un pacchetto strutturato con metadati verificabili:

json
{
  "smc_version": "1.0",
  "id": "container-fiscale-it-2025-q4",
  "domain": "fiscale/amministrativo",
  "jurisdiction": "IT",
  "valid_from": "2025-10-01",
  "valid_until": "2026-01-01",
  "schema": "procedure.v1",
  "signature": "ed25519:...",
  "modules": [
    {"name": "fatturazione-elettronica", "tokens": 12400},
    {"name": "regime-forfettario-2025", "tokens": 8900},
    {"name": "esterometro-nuove-regole", "tokens": 3200}
  ],
  "embeddings_index": "sha256:...",
  "tool_manifest": [
    {"name": "calcola_iva", "schema": "..."},
    {"name": "verifica_partita_iva", "schema": "..."}
  ]
}

Punti chiave:

  • valid_from / valid_until: scadenza legale incorporata — il runtime rifiuta container scaduti.
  • signature: catena di custodia. Il container è firmato dall'ente certificatore (commercialista, ordine professionale, produttore macchinari).
  • tool_manifest: dichiara quali tool il container abilita. L'SLM li chiama via XML standard; il container fornisce solo gli schemi.

Pattern Concreto: Injection Selettiva con Budget di Token

Il context window è risorsa scarsa. L'SLM deve comporre il contesto ottimale per il task. Ecco un pattern illustrativo per selezionare moduli .smc sotto budget:

rust
// Pattern illustrativo — selector concettuale
#[derive(Debug, Clone)]
pub struct SmcModule {
    pub name: String,
    pub tokens: usize,
    pub relevance: f32,
    pub required: bool,
}

pub fn select_modules(
    available: &[SmcModule],
    query_embedding: &[f32],
    token_budget: usize,
    required_domains: &[String],
) -> Vec<SmcModule> {
    let mut scored: Vec<_> = available.iter().cloned().map(|mut m| {
        m.relevance = cosine_similarity(query_embedding, &m.embedding);
        m
    }).collect();

    for m in &mut scored {
        if required_domains.iter().any(|d| m.name.starts_with(d)) {
            m.required = true;
        }
    }

    scored.sort_by(|a, b| {
        match (a.required, b.required) {
            (true, false) => std::cmp::Ordering::Less,
            (false, true) => std::cmp::Ordering::Greater,
            _ => (b.relevance / b.tokens as f32)
                .partial_cmp(&(a.relevance / a.tokens as f32))
                .unwrap()
        }
    });

    let mut selected = Vec::new();
    let mut used = 0;
    for m in scored {
        if used + m.tokens <= token_budget {
            used += m.tokens;
            selected.push(m);
        }
    }
    selected
}

Principi del pattern:

  • Embeddings locali calcolano similarità senza chiamate esterne.
  • Moduli required garantiscono copertura minima per il dominio.
  • Budget token configurabile per il modello target.

Coesistenza con Nova Kernel v3: Due Filosofie, Un Ecosistema

Mentre Silicea adotta un runtime SLM + container modulari per esecuzione locale e privacy, Nova (Nova Kernel v3, capability-based, P1 Gateway :3001, nova-conscience fail-closed con Candle Guard) esplora architetture di sicurezza cognitiva e message dispatching verificabile. Il Progetto Siliceo non vende modelli. Costruisce l'infrastruttura perché la conoscenza viaggi sicura, versione dopo versione, dentro il perimetro di chi la possiede.
