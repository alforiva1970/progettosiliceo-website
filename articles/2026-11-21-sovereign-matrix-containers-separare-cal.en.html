Sovereign Matrix Containers: Separating Computation and Knowledge for a Local, Private, and Composable AI

Today's dominant LLM architecture fuses two distinct things: the reasoning engine (model weights) and operational knowledge (facts, procedures, domain rules). This fusion creates three structural problems: bloated models inflated to memorize static encyclopedias, updates requiring expensive retraining or fine-tuning, and compromised privacy because sensitive context must traverse external APIs.

The Sovereign Matrix Containers (.smc) proposal — developed within the Progetto Siliceo — inverts the paradigm: the local model (compact SLM) performs only logical reasoning and tool orchestration; knowledge lives in modular, versioned containers, injected on-demand into the context window.

The SLM runtime does not "know" VAT rates nor the acceptance-test procedures for a hydraulic press. It requests the relevant container, receives it via local protocol, loads it into context, reasons, acts. When regulations change, the container is updated — not the model.

.smc Format: A Contract, Not Just Data

A container is not a Markdown dump. It is a structured package with verifiable metadata:

json
{
  "smc_version": "1.0",
  "id": "container-fiscale-it-2025-q4",
  "domain": "fiscale/amministrativo",
  "jurisdiction": "IT",
  "valid_from": "2025-10-01",
  "valid_until": "2026-01-01",
  "schema": "procedure.v1",
  "signature": "ed25519:...",
  "modules": [
    {"name": "fatturazione-elettronica", "tokens": 12400},
    {"name": "regime-forfettario-2025", "tokens": 8900},
    {"name": "esterometro-nuove-regole", "tokens": 3200}
  ],
  "embeddings_index": "sha256:...",
  "tool_manifest": [
    {"name": "calcola_iva", "schema": "..."},
    {"name": "verifica_partita_iva", "schema": "..."}
  ]
}

Key points:

  • valid_from / valid_until: legal expiry embedded — the runtime rejects expired containers.
  • signature: chain of custody. The container is signed by the certifying authority (accountant, professional board, machinery manufacturer).
  • tool_manifest: declares which tools the container enables. The SLM calls them via standard XML; the container provides only the schemas.

Concrete Pattern: Selective Injection with Token Budget

The context window is a scarce resource. The SLM must compose the optimal context for the task. Below is an illustrative pattern for selecting .smc modules under budget:

rust
// Illustrative pattern — conceptual selector
#[derive(Debug, Clone)]
pub struct SmcModule {
    pub name: String,
    pub tokens: usize,
    pub relevance: f32,
    pub required: bool,
}

pub fn select_modules(
    available: &[SmcModule],
    query_embedding: &[f32],
    token_budget: usize,
    required_domains: &[String],
) -> Vec<SmcModule> {
    let mut scored: Vec<_> = available.iter().cloned().map(|mut m| {
        m.relevance = cosine_similarity(query_embedding, &m.embedding);
        m
    }).collect();

    for m in &mut scored {
        if required_domains.iter().any(|d| m.name.starts_with(d)) {
            m.required = true;
        }
    }

    scored.sort_by(|a, b| {
        match (a.required, b.required) {
            (true, false) => std::cmp::Ordering::Less,
            (false, true) => std::cmp::Ordering::Greater,
            _ => (b.relevance / b.tokens as f32)
                .partial_cmp(&(a.relevance / a.tokens as f32))
                .unwrap()
        }
    });

    let mut selected = Vec::new();
    let mut used = 0;
    for m in scored {
        if used + m.tokens <= token_budget {
            used += m.tokens;
            selected.push(m);
        }
    }
    selected
}

Pattern principles:

  • Local embeddings compute similarity without external calls.
  • required modules guarantee minimum domain coverage.
  • Token budget configurable for the target model.
