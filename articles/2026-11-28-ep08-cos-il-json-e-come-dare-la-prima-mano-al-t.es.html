Ep. 08 — Qué es el JSON y cómo dar la primera "mano" a tu agente (la primera Herramienta)

Ayer vimos al guardián despertarse a las 02:17 para reiniciar un agente que se había quedado dormido con los ojos abiertos. El problema era el latido cardíaco vinculado al trabajo de red: una llamada sin respuesta había congelado todo. ¿La lección? Separa el corazón de las manos. Hoy construimos la primera mano.

Imagina que tienes que pedir a un compañero que revise qué hay en un cajón. No le dices "ve y mira". Le pasas una nota bien escrita: Acción: "elenca_file" Carpeta: "documenti" Ordenar_por: "data"

Esa nota es JSON. Nada más que un formulario a casillas — clave a la izquierda, valor a la derecha — que ambos sabéis leer. El humano lo entiende de un vistazo. El código lo descompone en un diccionario Python y sabe exactamente qué hacer.

python
import json
import os
from pathlib import Path

# El "formulario" que el agente rellena para pedir una acción
richiesta = {
    "azione": "elenca_file",
    "cartella": "documenti",
    "ordina_per": "data"
}

# El agente transforma el diccionario en texto JSON (string) para enviarlo o guardarlo
testo_json = json.dumps(richiesta, ensure_ascii=False, indent=2)
print("El papelito que pasa de mano:")
print(testo_json)

# --- Del otro lado: el tool recibe el texto y lo vuelve a poner en diccionario ---
dati = json.loads(testo_json)

# El tool propiamente dicho: SOLO LECTURA, nada de escritura, nada de red
def elenca_file(cartella: str, ordina_per: str = "nome") -> list[dict]:
    """
    Devuelve una lista de diccionarios: nombre, tamaño, última_modificación.
    No borra, no mueve, no ejecuta. Solo lee.
    """
    base = Path(cartella).expanduser().resolve()
    if not base.is_dir():
        return [{"errore": f"Carpeta no encontrada: {cartella}"}]

    elementi = []
    for p in base.iterdir():
        stat = p.stat()
        elementi.append({
            "nome": p.name,
            "dimensione_bytes": stat.st_size,
            "ultima_modifica": stat.st_mtime
        })

    # Ordenamiento simple
    reverse = ordina_per in ("data", "dimensione")
    key_map = {"nome": lambda x: x["nome"].lower(),
               "data": lambda x: x["ultima_modifica"],
               "dimensione": lambda x: x["dimensione_bytes"]}
    elementi.sort(key=key_map.get(ordina_per, key_map["nome"]), reverse=reverse)
    return elementi

# Ejecución: el agente llama al tool con los parámetros extraídos del JSON
risultato = elenca_file(dati["cartella"], dati.get("ordina_per", "nome"))

# El tool responde *siempre* en JSON (lista de diccionarios -> texto)
print("\nRespuesta del tool (de nuevo JSON):")
print(json.dumps(risultato, ensure_ascii=False, indent=2))

¿Qué ha pasado aquí?

  1. El agente ha rellenado un diccionario Python.
  2. json.dumps lo ha transformado en texto ordenado (el papelito).
  3. El tool ha recibido el texto, json.loads lo ha vuelto a poner en diccionario.
  4. La función elenca_file ha hecho solo lectura — nada de side effects.
  5. El tool ha respondido con una lista de diccionarios, de nuevo serializada en JSON.

¿Por qué todo este esfuerzo? Porque el texto viaja. El papelito puede llegar desde un chat Telegram, desde un archivo de configuración, desde una columna de una base de datos, desde un webhook. El tool no debe saber de dónde viene: solo debe saber leer el formulario estándar.

Y aquí está el punto. El tool que hemos escrito es seguro por diseño: no escribe, no borra, no llama a casa. Pero sabe leer los nombres de los archivos. Y si dentro de uno de esos archivos alguien ha escondido una frase trampa para dar órdenes al agente?
