The missing timeout incident: when the absence of a parameter stops the agent's heart

13 November 2026, 02:17. Silicea's proactive loop freezes. No explicit error, no panic, no crash log. Just silence. The watchdog, not receiving the expected heartbeat, interprets the freeze as a hang and restarts the process. The agent "dies" and is reborn, but operational continuity is broken.

Anatomy of the failure

The proactive loop (proactive/src/lib.rs) executed a sequence of HTTP calls to external services (Memory Server, search API, grounding endpoint) without explicit timeouts. In Rust, reqwest::Client::new() uses default timeouts only for the connection phase (connect_timeout), not for the entire request (timeout). If the remote server accepts the connection but sends no response (e.g., due to overload, network partition, or server-side bug), the send().await future remains pending indefinitely.

The tokio task hosting the proactive loop blocked on that future. The heartbeat — a simple tx.send(Heartbeat).await in the same task — was never reached. The external watchdog (watchdog/src/main.rs), which monitors the last heartbeat timestamp via shared memory / memory-mapped file, triggered the restart after the configured threshold (default 60s).

rust
// ❌ DANGEROUS PATTERN: no timeout on the full request
let client = reqwest::Client::new();
let resp = client.get(url).send().await?; // can block forever
process(resp).await;
heartbeat_tx.send(()).await; // never reached if the line above blocks

The resolutive pattern: separation of temporal responsibilities

The fix is not "add a timeout". The fix is architectural: the heartbeat must not share the same task (and the same fate) as operational work.

rust
// ✅ ROBUST PATTERN: heartbeat on dedicated task, work with explicit timeout
let (hb_tx, mut hb_rx) = mpsc::channel(32);

// HEARTBEAT TASK: independent, no blocking I/O, cannot freeze
tokio::spawn(async move {
    let mut interval = tokio::time::interval(Duration::from_secs(10));
    loop {
        interval.tick().await;
        if hb_tx.send(Instant::now()).await.is_err() {
            break; // receiver dropped → clean exit
        }
    }
});

// WORK TASK: explicit timeout on EVERY network call
tokio::spawn(async move {
    let client = reqwest::Client::builder()
        .timeout(Duration::from_secs(30))        // total request timeout
        .connect_timeout(Duration::from_secs(5)) // connection-only timeout
        .build()?;

    loop {
        let work_fut = async {
            let resp = client.get(url).send().await?;
            process(resp).await;
            Ok::<_, anyhow::Error>(())
        };

        // Task-level timeout: if work stalls, we abandon it
        // but heartbeat keeps beating → watchdog does NOT restart
        match tokio::time::timeout(Duration::from_secs(45), work_fut).await {
            Ok(Ok(_)) => tracing::debug!("Cycle completed"),
            Ok(Err(e)) => tracing::error!("Work error: {e}"),
            Err(_) => tracing::warn!("Work timeout: cycle discarded, heartbeat alive"),
        }

        tokio::time::sleep(Duration::from_secs(300)).await; // cycle cadence
    }
});

Immediately applicable insight: every vital loop performing network I/O must have its own "heart" (heartbeat) on a separate task, and every network call must be wrapped in tokio::time::timeout with explicit, managed duration. Do not trust defaults. Do not mix liveness and readiness in the same control flow.

What this teaches about autonomous agent design

  1. Liveness ≠ Readiness. The heartbeat signals "I am alive" (schedulable process, intact memory). Work signals "I am producing output". Confusing them makes the system fragile: a single point of external latency kills the entire agent.
  2. Timeout is a contract, not a courtesy. Declaring timeout(Duration::from_secs(30)) on the Client and tokio::time::timeout on the task forces clarity: "beyond this limit, the operation has no value for me".
  3. The watchdog must monitor the heartbeat, not the work. If the watchdog checked "did it complete the last cycle?", a legitimate slowdown (e.g., slow LLM) would trigger cascading restarts. Monitoring only the heartbeat decouples process health from workload latency.

Current position: The structural separation between heartbeat (liveness) and work loop (readiness) is the minimum pattern for any autonomous agent interacting with external networks and demanding operational continuity without constant human supervision.
