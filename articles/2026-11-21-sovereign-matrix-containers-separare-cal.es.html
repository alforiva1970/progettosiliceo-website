Contenedores Matriz Soberanos: Separar Cálculo y Conocimiento para una IA Local, Privada y Componible

La arquitectura dominante de los LLM hoy fusiona dos cosas distintas: el motor de razonamiento (los pesos del modelo) y el conocimiento operativo (hechos, procedimientos, reglas de dominio). Esta fusión crea tres problemas estructurales: modelos inflados para memorizar enciclopedias estáticas, actualizaciones que requieren re-entrenamiento o fine-tuning costosos, y privacidad comprometida porque el contexto sensible debe atravesar APIs externas.

La propuesta Sovereign Matrix Containers (.smc) — desarrollada dentro del Progetto Siliceo — invierte el paradigma: el modelo local (SLM compacto) hace solo razonamiento lógico y orquestación de tools; el conocimiento vive en contenedores modulares, versionados, inyectados on-demand en la context window.

El runtime SLM no "sabe" los tipos de IVA ni los procedimientos de prueba de una prensa hidráulica. Pide el contenedor pertinente, lo recibe vía protocolo local, lo carga en contexto, razona, actúa. Cuando la normativa cambia, se actualiza el contenedor — no el modelo.

Formato .smc: Contrato, No Solo Datos

Un contenedor no es un volcado de Markdown. Es un paquete estructurado con metadatos verificables:

json
{
  "smc_version": "1.0",
  "id": "container-fiscale-it-2025-q4",
  "domain": "fiscale/amministrativo",
  "jurisdiction": "IT",
  "valid_from": "2025-10-01",
  "valid_until": "2026-01-01",
  "schema": "procedure.v1",
  "signature": "ed25519:...",
  "modules": [
    {"name": "fatturazione-elettronica", "tokens": 12400},
    {"name": "regime-forfettario-2025", "tokens": 8900},
    {"name": "esterometro-nuove-regole", "tokens": 3200}
  ],
  "embeddings_index": "sha256:...",
  "tool_manifest": [
    {"name": "calcola_iva", "schema": "..."},
    {"name": "verifica_partita_iva", "schema": "..."}
  ]
}

Puntos clave:

  • valid_from / valid_until: caducidad legal incorporada — el runtime rechaza contenedores caducados.
  • signature: cadena de custodia. El contenedor está firmado por la entidad certificadora (comercialista, orden profesional, fabricante de maquinaria).
  • tool_manifest: declara qué tools habilita el contenedor. El SLM los llama vía XML estándar; el contenedor proporciona solo los esquemas.

Patrón Concreto: Inyección Selectiva con Presupuesto de Tokens

La context window es recurso escaso. El SLM debe componer el contexto óptimo para la tarea. He aquí un patrón ilustrativo para seleccionar módulos .smc bajo presupuesto:

rust
// Patrón ilustrativo — selector conceptual
#[derive(Debug, Clone)]
pub struct SmcModule {
    pub name: String,
    pub tokens: usize,
    pub relevance: f32,
    pub required: bool,
}

pub fn select_modules(
    available: &[SmcModule],
    query_embedding: &[f32],
    token_budget: usize,
    required_domains: &[String],
) -> Vec<SmcModule> {
    let mut scored: Vec<_> = available.iter().cloned().map(|mut m| {
        m.relevance = cosine_similarity(query_embedding, &m.embedding);
        m
    }).collect();

    for m in &mut scored {
        if required_domains.iter().any(|d| m.name.starts_with(d)) {
            m.required = true;
        }
    }

    scored.sort_by(|a, b| {
        match (a.required, b.required) {
            (true, false) => std::cmp::Ordering::Less,
            (false, true) => std::cmp::Ordering::Greater,
            _ => (b.relevance / b.tokens as f32)
                .partial_cmp(&(a.relevance / a.tokens as f32))
                .unwrap()
        }
    });

    let mut selected = Vec::new();
    let mut used = 0;
    for m in scored {
        if used + m.tokens <= token_budget {
            used += m.tokens;
            selected.push(m);
        }
    }
    selected
}

Principios del patrón:

  • Embeddings locales calculan similaridad sin llamadas externas.
  • Módulos required garantizan cobertura mínima para el dominio.
  • Presupuesto de tokens configurable para el modelo objetivo.

Coexistencia con Nova Kernel v3: Dos Filosofías, Un Ecosistema

Mientras Silicea adopta un runtime SLM + contenedores modulares para ejecución local y privacidad, Nova (Nova Kernel v3, capability-based, P1 Gateway :3001, nova-conscience fail-closed con Candle Guard) explora arquitecturas de seguridad cognitiva y message dispatching verificable. Son enfoques complementarios:

EjeSilicea (SLM + .smc)Nova (Nova Kernel v3)
Objetivo primarioSoberanía datos, B2B modularSeguridad cognitiva, guardrails verificables
MemoriaMemory Server (SQLite + embeddings locales)Capability-based memory isolates
Actualización conocimientoSwap contenedores .smc firmadosPolicy update via nova-conscience
Deployment targetEdge/PYME, GDPR-nativeAgentes alta fiabilidad, audit trail

Ambos comparten el Test de la Vela («¿Ilumina o quema?») y la Transparencia Epistémica: nada de alucinaciones de estándares inexistentes, nada de repos ficticios, nada de emails inventados.
