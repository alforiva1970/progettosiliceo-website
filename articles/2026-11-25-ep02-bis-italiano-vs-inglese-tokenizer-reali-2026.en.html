Ep. 02-bis — Italian vs English: the same sentence across 5 real 2026 tokenizers

Under our TikTok episode on tokens, Byte Aster Arca (@byte.aster.arca) asked two sharp questions:

  1. How much does the token count change between the same sentence in Italian and in English?
  2. How does that count shift across different model tokenizers, not just across languages?

No guesswork: we took five official tokenizers in production in late 2026 and counted every single brick.

The experiment: one exact sentence, two languages, five models

We picked a short everyday sentence containing an apostrophe and a compound word:

  • Italian: "L'intelligenza artificiale non legge le parole: conta mattoncini."
  • English: "Artificial intelligence doesn't read words: it counts bricks."

Here are the measured counts (excluding special start/end tokens):

Two immediate surprises stand out:

  1. Across the four global generalist models, Italian costs +25.0% to +70.0% more tokens than English for the exact same meaning.
  2. Emma-6 has the smallest vocabulary of all (64,000 pieces, less than a quarter of Gemma 4's 262,144), yet it beats every other model on Italian (13 tokens) and uses one fewer token in Italian than in English (14). Why? Because its 64,000 bricks were carved around Italian.

Inside the bricks: the same text cut through different eyes

In English, OpenAI GPT-6 (o200k_base) keeps almost every word intact — 10 exact bricks:

[Artificial] + [ intelligence] + [ doesn't] + [ read] + [ words] + [:] + [ it] + [ counts] + [ bricks] + [.]

In Italian, the very same o200k_base has to split much more — 17 bricks:

[L] + ['int] + [elligen] + [za] + [ artific] + [iale] + [ non] + [ legge] + [ le] + [ parole] + [:] + [ conta] + [ mat] + [ton] + [c] + [ini] + [.]

Compare that with Emma-6 on the exact same Italian sentence (13 bricks):

[ L] + ['] + [intelligenza] + [ artificiale] + [ non] + [ legge] + [ le] + [ parole] + [:] + [ conta] + [ matton] + [cini] + [.]

Both "intelligenza" and "artificiale" fit into a single brick each, and "mattoncini" splits into 2 pieces instead of 4.

Honest check on Ep. 02: "intelligenza" vs "intelligence"

In Episode 02 we showed "intelligenza" split into 3 pieces. On real 2026 tokenizers, the split depends on the model:

  • OpenAI GPT-6 (o200k_base) and Mistral Ministral 3: 3 pieces in IT (int + elligen + za) vs 2 in EN (int + elligence).
  • Alibaba Qwen 3.8: 2 pieces in IT (int + elligenza) vs 1 whole brick in EN (intelligence).
  • Google Gemma 4: 2 pieces in IT (intell + igenza) vs 1 whole brick in EN (intelligence).
  • Egomnia Emma-6: 1 whole brick in IT (intelligenza) and 1 in EN (intelligence).

Control check on a longer sentence

We repeated the measurement on a full agentic sentence: IT: "Un agente autonomo osserva l'ambiente, decide l'azione giusta e verifica il risultato senza inventare dati." EN: "An autonomous agent observes the environment, chooses the right action, and verifies the result without inventing data."

The pattern holds: GPT-6 25 IT vs 21 EN (+19.0%), Qwen 3.8 24 vs 21 (+14.3%), Gemma 4 24 vs 20 (+20.0%), Ministral 3 26 vs 22 (+18.2%), Emma-6 21 vs 26 (-19.2%).

Try it on your workbench (15 lines of Python)

If you followed Ep. 04, install tiktoken (pip install tiktoken) and count the real o200k_base bricks yourself:

python
import tiktoken

# Load GPT-6's real vocabulary (o200k_base, 200,019 tokens)
enc = tiktoken.get_encoding("o200k_base")

sentences = {
    "IT": "L'intelligenza artificiale non legge le parole: conta mattoncini.",
    "EN": "Artificial intelligence doesn't read words: it counts bricks.",
}

for lang, text in sentences.items():
    ids = enc.encode(text)
    pieces = [
        enc.decode_single_token_bytes(i).decode("utf-8", errors="replace")
        for i in ids
    ]
    print(f"{lang} -> {len(ids)} tokens: {pieces}")

What you take home (wallet, memory, and model)

  1. Both language and dictionary matter: for the same meaning, Italian fills the context board faster and uses more tokens on global generalist models.
  2. Vocabulary size isn't everything: what truly decides token efficiency is the language distribution the tokenizer was trained on.
